# 逐功能实机验证清单（LIVE_TEST_PLAN）

> 目的：把 companion 新增/修改的每一个功能**单独**测一遍，
> 测甲功能时把其它开关全部关掉，排除干扰项。
>
> 配套：`docs/KNOWLEDGE_BASE.md`（逆向结论）、
> `San9Features.ini`（开关文件）、`out/trial/`（试用包）。

---

## 0. 通用流程

### 0.1 准备

1. 解压 `out/trial/` 到**游戏主目录**（与 `San9PK.exe` 同目录）。
2. 确认同目录有 `San9Features.ini`。
3. 建议先备份存档。

### 0.2 开关文件用法

`San9Features.ini` 与 exe 同目录，**启动时读一次**，运行期不再写回。

```
[Features]
DeathGradient=1
GrowthBoost=1
...
```

- 值只能是 `0` 或 `1`；**其它值一律按 0**（手误不会打开功能）。
- 缺键 = 默认（默认全部 `1`）。
- **改完必须重启修改器**。

### 0.3 每次测试的标准步骤

1. 编辑 `San9Features.ini` → 只留一个功能为 `1`，其余全 `0`。
2. 启动 `San9Companion.exe`。
3. 启动 `San9PK.exe`，进存档。
4. 在修改器里确认配置（点「确认」）。
5. 观察游戏内表现。
6. 看日志（`San9Companion.log`，与 exe 同目录）里的
   `FEATURES: summary=...` 与 `FEATURE xxx : off/on` 行，确认开关真的生效了。
7. 关闭游戏与修改器，做下一项。

> ⚠️ **关掉其它开关的意义**：2019 工具遗产的约 300 个 hook 是**无条件安装**的
> （它们没有单独开关）。逐功能开关只覆盖**我们这一轮新增/修改**的功能。
> 所以「只测一个功能」= 关掉其它 12 个**我们的**开关。

### 0.4 日志怎么读

| 日志行 | 含义 |
|---|---|
| `FEATURES: file=... summary=1 0 1 ...` | 开关总览，顺序与 ini 一致，1=on 0=off |
| `FEATURE xxx : off, nothing is injected` | 该功能**完全没注入** |
| `FEATURE xxx : on, ...` | 该功能已注入 |

## 3. 出问题怎么定位

### 3.1 二分法

某功能崩溃时：

1. 把 `San9Features.ini` 里**全部**置 `0`，只留出问题的那一项为 `1`。
2. 若仍崩 → 问题不在我们的功能（可能是 2019 遗产 hook 或游戏本身）。
3. 若不崩 → 逐个加回其它项，找到触发组合。

### 3.2 看日志

- `San9Companion.log` 与 exe 同目录。
- 需要每次内存写入都记录：修改器 → 设置 → 扩展设置 → 详细日志。
- 崩溃后 Windows 会在
  `%LOCALAPPDATA%\CrashDumps\` 留下 `San9PK.exe.<pid>.dmp`，
  把它一起给我。

### 3.3 开关值写错

`San9Features.ini` 里写 `true` / `yes` / `2` 都会被当成 **0（关）**。
这是故意的：手误不应该打开一个功能。日志里的 `summary=` 能立刻看出读成了什么。
